Checked on 2026-11-03 (UTC) from public documentation only, for plan
[`2026-11-04-phase-8-5-veo-media.md`](../../plans/2026-11-04-phase-8-5-veo-media.md) WP1 step 4. No Veo endpoint
was called and no key was read. Where the documentation is silent the pipeline keeps the behaviour that plan 06's

## Findings

| Question | Finding | Effect on the pipeline |
|---|---|---|
| Model id | `veo-3.1-fast-generate-001` and `veo-3.1-generate-001` are listed as GA on Vertex AI. The Gemini API page lists only `veo-3.1-*-preview` ids and says those preview models shut down on 2026-10-22. | The default stays `veo-3.1-fast-generate-001`. If the key is a Gemini API key (not `AQ.`), the model may not exist there: `veo-preflight` shows this for free before the pilot (WP3 step 2). |
| `durationSeconds` | Veo 3.1 accepts 4, 6 or 8 seconds; reference-image-to-video (`referenceImages`) only 8. | 4 s is the minimum and stays. The pipeline sends a first-frame `image`, not `referenceImages`; plan 06's live runs used `image` with 4 s and succeeded. |
| `generateAudio` | Sound generation is "supported" for both 3.1 models. A search snippet of the API reference says the field is required for Veo 3 models, and a forum report says the Gemini API rejects it. | Not sent, as in plan 06's working live requests. The baker discards audio. Whether `generateAudio: false` lowers the cost is not documented; not tested, because testing it costs a generation. |
| `storageUri` | Optional Cloud Storage destination. Plan 06 recorded the live Vertex response without it as inline `bytesBase64Encoded`. | Never sent. A `gcsUri` result is recorded and stops the run (D-5); `generate-veo --import` installs a hand-fetched clip against its recorded operation. |
| `personGeneration` | Not shown on the pages read. | Not sent; prompts describe machines and structures, with "no characters" for structures (D-2). |
| `sampleCount`, `aspectRatio` | Up to 4 videos per prompt; 16:9 and 9:16. | Unchanged: 1 sample, 16:9. |
| Prompt length | No limit is published for the 3.1 models. Third-party catalogues quote a 1K-token context, unverified. | `max_prompt_chars: 1024` in `assets/catalog/media_style.ron`, checked by `validate-prompts`. |
| Quota error shape | Google APIs report quota exhaustion as HTTP 429 with `error.status = "RESOURCE_EXHAUSTED"`; Vertex lists a per-minute regional request quota per base model. | A start request answered 429 with `RESOURCE_EXHAUSTED` or a message naming a quota ends the run with exit code 3 and a `quota_refused` ledger line (D-4). A per-minute limit also ends it: waiting costs nothing. A plain 429 is still retried, because it started no work. |
| Preflight resource | Gemini API: `GET v1beta/models/{model}` is the documented model resource. Vertex: the publisher model resource is `projects/{project}/locations/{location}/publishers/google/models/{model}`; whether express mode serves a GET on it is not documented. | `veo-preflight` GETs the Gemini model resource, or for an `AQ.` key the project-scoped Vertex model resource on the same host and path that generation uses. A 404 or 501 there may mean express mode does not serve the GET rather than a bad key; the printed `Error status` tells them apart (`PERMISSION_DENIED`/`UNAUTHENTICATED` versus `NOT_FOUND`/`UNIMPLEMENTED`). |
