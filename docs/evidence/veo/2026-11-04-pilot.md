## Step 2: preflight (free GET), failed

Command, run from the WP3 worktree, with the key read only by the tool from the main checkout:

```text
asset_baker veo-preflight --credentials-dir /home/spacescuffle/space-scuffle
```

The complete output (checked for key-like strings: none):

```text
Mode: Vertex AI Express
Model: veo-3.1-fast-generate-001
HTTP status: 404
Model visible: no
Error: the key cannot read model 'veo-3.1-fast-generate-001' (HTTP 404)
```

Exit code 1. No `Error status:` line was printed, so the 404 body was not a Google JSON error carrying
`error.status`. The tool GETs the project-scoped publisher model resource
(`v1/projects/{project}/locations/us-central1/publishers/google/models/{model}`) on the generation host.

**What it means.** The API notes
([`2026-11-04-api-notes.md`](2026-11-04-api-notes.md), "Preflight resource") recorded that the documentation does not
say whether Express mode serves a GET on that resource, and that a 404 there may mean the route is not served rather
than a bad key. The result cannot tell the two cases apart:

1. Express mode does not serve the model GET. The key, project and model may then still work for
   `predictLongRunning`, as plan 06's live runs did with this mode.
2. The key, the project read with it, or the model id is not valid for generation.

A pilot generation would tell them apart. It could cost one generation, so this package does not start it without
the owner's decision.
