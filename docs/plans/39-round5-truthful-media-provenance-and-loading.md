# Round 5: Truthful media baking, provenance and exact runtime loading

> Evidence under /tmp in this document was on the development notebook and was not retained (Q-10, 2026-11-03).

Status: orchestrator approved; stage-one audit, unsafe batch removal and exact runtime loading implemented, verification in progress. The orchestrator released implementation after the shared gate exposed a separately tracked pathfinding performance failure; that gate is not accepted. Broader declared baking follows as a separate stage. Preserve all art files. No external generation, credential inspection or editor work.

## Goal and non-goals

Stop production tooling from relabeling one concept video as an entire roster, stop the graphical client from silently binding another archetype's media, and make the provenance and actual availability of every requested unit/action inspectable. New baking must require explicit authored inputs; runtime errors must identify the real missing/malformed asset and propagate visibly. This round establishes truthful software/data contracts. It cannot certify that current media depicts the intended creature/action or invent missing authentic footage.

Do not regenerate the existing textures, synthesize alpha from luminance, turn stills into fake animation, reuse another creature's movie, silently alias an idle sequence as attacks/death, or invoke a paid video service. Actual artistic replacement and approval require a separately scoped media-production round. Do not change combat, simulation catalog semantics, map terrain, optics shaders, or editor paths.

## Verified current defects and inventory

Read-only inventory of both `assets/catalog/units.ron` and `structures.ron` found 91 distinct catalog slugs. Ten have own-name PNG and metadata pairs; 81 have no own PNG. Inventory with exact hashes, dimensions, source filenames and alpha extrema is preserved at `/tmp/space-scuffle-r4-media-inventory.json`; implementation must reproduce this through typed catalog parsing rather than the planning script's textual scan.

Six differently named PNGs are byte-for-byte identical to `assets/textures/concept_video.png`: `welder_drone`, `railgun_crawler`, `flying_saucer`, `capacitor_dome`, `assembly_bay_dome`, and `tesla_sentinel_dome`. Their paths are evidence, not identifiers to branch on in Rust. The other own-name pairs are `pulse_bot`, `rhino_beetle`, `psi_grey`, and `foundry_core_dome`; these four have named idle/walk/attack MP4 files. Filenames alone do not prove provenance or action correctness. No existing source-to-output digest record establishes that those particular videos produced the installed atlas. All ten PNGs have alpha extrema `(255,255)`: they are opaque studio images. Opaque pixels are not evidence of a valid transparent cutout, but opaque studio presentation is historically documented in the art guide; this round must report that fact without fabricating transparency or declaring opaque media inherently malformed.

The actual current paths causing the defects are:

1. `asset_baker::bake_starter_units_from_real_video` loops over the compiled default catalog and calls `bake_custom_video` with the same source for every slug. It then ignores failure of the additional concept copy with `if let Ok`. `generate-defaults` falls back to procedural atlases when the concept video is absent and declares completion.
2. `ffmpeg_importer::extract_and_pack_video` documents an empty action map as Idle-only but actually maps all six states to the entire clip. Multi-action baking fills absent states with other actions' slices and silently truncates decoded clips to fit storage. Both frame-directory readers discard I/O errors with `filter_map(Result::ok)`.
3. `setup_bubble_assets_system` silently ignores file/parse/decode failures and populates missing registry slots with another archetype's texture/metadata by faction/shape. Consumers also select neutral fallback handles. A native negative test proved a missing starting-building PNG still rendered and completed until the capture-only exact-media guard was added.
4. The default battle requires a worker whose own PNG is one of the concept copies. Therefore checking only own-name files removes registry substitution but does **not** establish authentic default-battle art. This distinction must remain visible in the audit and acceptance report.

## Scope and dependency boundaries

Own new `asset_baker::media_sources`, `asset_baker::media_audit` and narrow manifest/importer/CLI integration; new client media loading/status module; the loading block and registry contracts in `bubble_shader.rs`; and exact consumer admission in `scene_controller.rs` plus the existing UI error surface. Coordinate those client files with the UI/optics owners before edits. Reuse the existing external `RuntimeCatalogs` API; do not reintroduce compiled default catalogs into CLI production batch selection. No changes to authoritative sim state/checksum are required.

Keep reusable media/source schemas and CPU validation in `asset_baker`, which already depends on `sim_core` and `sim_types`; the client may consume those schemas without adding Bevy to any simulation crate. Use ordered maps and stable slug ordering for audit output. Content digests may use the already locked BLAKE3 package as an explicit dependency; record algorithm and digest encoding in the versioned file. Digests prove content identity and reproducibility, never visual authenticity.

## Explicit source declarations and new bakes

Add a strict versioned RON `MediaSourceCatalog` with `deny_unknown_fields`. Each entry names one external catalog slug and explicitly declares source paths and action mappings. A suitable model is `UnitMediaSource { slug, actions: BTreeMap<AnimState, SourceClip>, frame_size, fps, alpha_policy }`, where `SourceClip` supplies a real video path and an explicit full-clip or bounded time interval. Decode source timestamps as an exact rational/integer time unit at this offline boundary; validate finite/nonnegative ordering and representable FFmpeg arguments. Avoid float defaults that accidentally select different clips.

Paths resolve relative to the declaration file; reject empty paths and unsupported media sources. Canonicalize and retain the resolved input path in failures/provenance. Slugs must resolve uniquely through the loaded external catalog. Reject duplicate entry/action keys and duplicate output destinations before any subprocess or output mutation. Two differently named unit entries referring to identical source bytes should be a typed `CrossArchetypeSourceReuse` error by default. A future intentional shared presentation would need a separate explicit shared-media identity; do not add a permissive boolean that launders accidental reuse in this round.

The presence of a source clip is not an automatic claim that all actions exist. New bakes emit only declared action slices. Required action coverage is an explicit request to the baker and checked against declared inputs; it must never be filled by inferred idle/attack aliases. Runtime requests for missing actions fail with a typed diagnostic. Preserve existing atlas files and their historical action maps; the audit labels duplicated slice ranges for review rather than rewriting them.

Expose `bake_declared_media(catalog, sources, output_dir, policy) -> Result<BakeReport, MediaBakeError>`. Preflight the entire requested batch and record source hashes before execution. The default output policy must refuse existing destinations; stage outputs in a sibling temporary directory, validate all PNG/metadata/provenance triplets, then publish the new bundle only after the batch is complete. A failed batch leaves no newly accepted partial bundle and never overwrites existing art. Do not attempt a fragile multi-file in-place replacement transaction. Explicit replacement, if later required, should use a separately reviewed versioned-bundle promotion command.

Each result gets a provenance sidecar containing format version, external catalog slug, source paths and digests, declared action/time intervals, decoding/packing settings, FFmpeg version, source frame counts, emitted frame counts, alpha policy/observed range, and PNG/metadata digests. No local wallclock or machine path is part of the content identity; absolute paths may appear only as optional diagnostic origin information. The provenance describes exactly what ran, not an artistic approval certificate.

Do not silently truncate an overlong clip. With the present vertical-strip format, overflow of the supported dimensions/layer bounds is a typed error containing requested and supported counts. Authors may provide a shorter explicit interval or lower declared output size/rate; do not auto-select either. Use checked arithmetic for frame sizes, bytes, frame offsets, action range ends and strip heights before allocating. Validate against both the storage format and the actual client's texture-array limits; do not repeat the incorrect assertion that every WebGPU device necessarily supports a 16384-pixel 2D texture.

Propagate frame-directory enumeration errors and every mandatory concept/provenance output error. Explicitly designated concept media may still be baked as a concept asset through its own command; it cannot be a default roster input.

## CLI and compatibility strategy

Add `audit-media --catalog-dir ... --assets ... [--sources ...] --report ...` and `bake-media --catalog-dir ... --sources ... --output-dir NEW_DIRECTORY`. Audit must never invoke FFmpeg generation or rewrite files. Baking consumes the supplied external catalog at call time, so roster changes require no Rust changes.

Remove the dangerous behavior of `generate-defaults`: preserve the command spelling only as a clear typed migration error directing callers to explicit source declarations, or replace its arguments with `--sources` if there are no downstream users. Do not silently reinterpret its single-video invocation as permission to populate the roster. Similarly retain the old public `bake_starter_units_from_real_video` signature only as a deprecated, explicit `ExplicitSourcesRequired` error until removed; it must perform no output writes. Document this intentional behavioral incompatibility because the old behavior violates the project charter. Keep `bake_custom_video` for one explicitly named asset, but empty actions mean Idle only as documented. Keep procedural algorithm APIs for their existing algorithmic tests; remove automatic production fallbacks and do not claim those fixtures are authentic game media.

The Veo/network API implementation is outside this round. Its eventual output must enter the same explicit source/provenance path; do not autoinvoke it when a declared local file is missing. If credentials/service/source footage are unavailable in a later generation round, report the missing prerequisite and continue independent engineering work without creating replacements.

## Runtime exact binding and error propagation

Extract one fallible CPU loader used by graphical startup: `load_unit_media(root, archetype) -> Result<LoadedUnitMedia, MediaLoadError>`. It reads that slug's exact PNG/metadata, validates name, supported layout, true image dimensions, frame count/action ranges and GPU-admissible dimensions using checked arithmetic, then returns decoded bytes and metadata. Errors retain unit slug, requested action where applicable, actual path and typed I/O/parse/decode/representation cause.

The startup registry records per-archetype results, not a replacement image. Store successful assets in `Loaded` entries and explicit unavailable errors in a parallel ordered status map. Unknown/missing catalog entries, unavailable image data and unsupported action slices remain distinguishable. Never populate a missing ID by faction, shape or first available texture. Do not create a neutral texture as a production admission path.

Validate the required initial battle roster/showcase set before claiming graphical readiness, and validate every later newly requested entity/action before material creation/update. This permits a catalog to describe future, currently unrendered units without allocating their media every frame; requesting one with absent media produces a visible failure rather than rendering another creature. Load/validate once; use stable ID lookups without per-frame filesystem I/O, heap allocation or nested roster scans. The existing capture media validator should eventually delegate common representation checks to the new CPU loader, while retaining its independent check that the visible material actually binds those bytes.

Add a narrowly scoped `ClientMediaStatus`/typed error resource consumed by the normal startup/sync/UI paths. When a requested material/action is unavailable, retain the detailed diagnostic, stop the relevant simulation progression, display the reason through the existing UI error surface and return nonzero for native/headless verification runners. Do not overload combat events or silently omit an entity and continue a successful game. Include the failure in capture manifests via the same client status. Headless math/simulation tests must not claim to validate media; real renderer tests must use the actual valid selected asset set or explicitly test rejection. Preserve embedding API compilation where practical, but no compatibility mode may silently pass production render verification with aliases.

The exact-binding error surface belongs in this round; a wholesale UI redesign does not. Coordinate any error panel integration with plan36's data-driven HUD work and preserve its ordinary 1280×720 acceptance requirements.

## Provenance audit and unresolved legacy-art boundary

Audit outputs stable machine-readable and human-readable records for every catalog slug: exact pair availability, metadata validity/identity, action coverage and duplicated slices, output/content digest, duplicate media groups (including explicit concept assets), observed alpha range, declared source availability, and provenance verification status. Use statuses such as `VerifiedBuildInputs`, `LegacyUnverified`, `KnownConceptDuplicate`, `MissingAsset`, `MalformedAsset`, and `DigestMismatch`; none is named `Authentic` or `ArtistApproved` on the basis of hashes alone.

Do not invent provenance sidecars for old images by guessing from filenames, existing timestamps, or similar appearance. If a source declaration is later authored for the four named video sets, validate it through an actual staged bake and comparison; a different output requires separate artistic review before promotion. The six concept-copy identities must stay explicitly rejected as unit-specific visual content in the audit.

A necessary migration decision for orchestrator approval: exact runtime binding and artistic/provenance admission are distinct. This blueprint recommends making missing/corrupt/substituted bindings fatal immediately, while preserving existing own-file legacy pixels and publishing their explicit audit status; `audit-media --strict` remains nonzero for the current default bundle, and neither gameplay screenshots nor releases may call that bundle artistically accepted. Requiring fully approved unit-specific provenance at ordinary launch instead would correctly block the current default scenario because its worker has only concept-copy media. That stricter launch policy requires supplying authentic worker footage first; it cannot honestly be solved with a software fallback. The orchestrator must choose this migration boundary before implementation, rather than the implementer silently accepting legacy art or breaking normal startup.

## Missing authentic inputs, precisely

The default battle's initial rendered set has own files for all requested IDs, but the worker's file is an exact concept duplicate with no own named video source. Authentic unit-specific worker movement/idle/action footage is therefore the first actual art prerequisite; a still keyframe exists but is not an animation substitute. The other five exact concept duplicates likewise need unit-specific sources before visual acceptance. Eighty-one catalog entries have no own PNG at all and remain unavailable for rendering until real media is supplied. Four units/buildings have named video source sets, but their provenance/action quality and opaque-background treatment still need review; the presence of those files does not certify them. The inventory report provides the complete stable list, including paths, without adding creature identifiers to Rust.

## Tests and evidence

1. Parse strict authored source declarations: duplicate slugs/actions, unknown catalog slugs, unsafe destinations, missing video, repeated source content under different unit identities, invalid intervals/rates/sizes and unknown fields produce typed preflight failures without writes.
2. Test deterministic audit ordering and real current inventory. At least one checked-in real own-media pair must validate structurally; missing/corrupt/misnamed pairs and exact duplicate content must be reported. A generated test PNG is allowed only for dimension/error algorithms, never visual acceptance.
3. Exercise real FFmpeg on existing local clips into temporary new output bundles. Confirm declared action slices only, no synthetic missing actions, complete provenance hashes and explicit overflow. Do not mock an FFmpeg success to claim real media baking.
4. Failed batch preparation/decoding/output/provenance writes leave the destination absent or unchanged; existing output refusal preserves byte hashes. Test the deprecated single-concept batch path returns an error without any files.
5. Loader integration: remove one required PNG in an isolated symlink/copy asset root, corrupt metadata, alter image dimensions, select a missing action and create a catalog unit without media. Required render attempts must report the exact failure, produce no substituted material and exit nonzero. Unrequested missing entries remain inspectable in the availability report rather than being silently materialized.
6. Real `battle_capture` with the unchanged actual available bundle must verify exact bindings and capture the normal startup/tab/reset path. Preserve previous artistic rejections and compare logical manifests. If stricter provenance-at-launch policy is chosen, this is an explicitly blocked acceptance prerequisite until authentic worker media exists; do not weaken tests or secretly replace the scenario.
7. Run complete workspace tests, strict Clippy and fmt after coordinated source freeze. Existing editor diagnostics remain outside scope and are reported rather than altered.

Acceptance must separately state software integrity, exact runtime bindings, provenance completeness and artistic approval. Passing one category is not evidence for another.


## Orchestrator approval decisions and staged execution

The orchestrator selected the recommended migration boundary: missing/corrupt/aliased bindings become fatal, existing own-file legacy media remains unchanged with explicit unapproved audit status, and strict audit/release acceptance remains failing for concept duplicates and missing assets. This is not approval of default-game art. Stage the read-only audit, unsafe single-concept batch removal, and exact client loader before the broader declared baking/provenance publisher. Coordinate `ClientMediaStatus` and actual error presentation with plan36's owner before client edits.

Provenance must never certify bytes different from those FFmpeg decoded. For future declared baking, snapshot each source into a private staging directory before hashing/decoding. Hash that immutable staged copy and verify the original pre/post-copy digest and size agree with the staged bytes; any mismatch yields typed `InputChangedDuringCapture` before publication. FFmpeg receives only the staged path. Verify its digest again after decoding and reject unexpected staged changes. Do not hash the original once and then decode a mutable pathname. Source snapshots and all result files belong to the same failed-or-published staging transaction; no live source or existing output is rewritten.


## Stage-one presentation failure policy

Ordinary unbounded gameplay retains a readable failure panel and paused progression until the user closes the window; shared fatal evidence forces that eventual orderly close to return nonzero. Automated frame-limit and capture runners select explicit immediate failure. First-error text and typed evidence survive simulation resets and tab changes; neither operation replaces the asset bundle. The plan36 inspector consumes cached status/error text and keeps provenance detail collapsed. This policy requires actual native screenshot verification before claiming readable failure presentation.
