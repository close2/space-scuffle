- Positions/differences use i128 raw subtraction. Scalar distances square unsigned differences in u128, sum with overflow checking and take integer square root before any i64 narrowing. Underflow to zero retains the defined quantization; overflow is a typed error, not saturation, wrapping or an arbitrary gameplay cap. A later reciprocal does not legalize an unrepresentable earlier ordered stage.
- Numeric correctness does not tune movement balance. Preserve valid speed limits, friendly push factors, hold/priority branches, current collision policy, final-arrival logic and pathfinder clearance classes. Widened geometry can change low raw bits; record that honestly and verify meaningful ordinary behavior and same-build replay rather than assert old checksum parity.

Preparation uses a small pose/order/route-edit proposal (copy scalar fields, retain optional newly generated route ownership, record waypoint removal count/order completion). It does not clone an Entity, order queue, existing waypoint Vec, or complete world per actor. Existing route slices can be examined without mutation; commit performs the planned edits only after arithmetic and terrain decisions succeed. Cheap bounded loop counters, constant fractions, and sin/cos table operations need their range proof, not gratuitous Result wrappers. This preserves error atomicity without rebuilding every data structure or rediscovering identical policy per helper.

The contract is per movement operation, not rollback of a whole completed simulation tick. Earlier successful actors/phases remain committed, as with existing32/43 diagnostics, and the client must retain completed-tick evidence before halting further advancement. Ordinary blocked terrain remains a normal nonmoving result; arithmetic corruption is distinct fatal evidence.

For an individual Move/pursuit update, prepare its selected route/snap/steering result, new position/velocity/heading/animation and planned order/waypoint edits before committing any of those fields. In particular, do not clear an Air route, update `pos_at_tick_start`, pop a waypoint or cancel an order and then discover arithmetic failure. Existing pathfinder scratch can mutate as derived workspace; a newly produced route Vec can remain owned in the local proposal until commit. Preserve/reuse capacities where possible without an entity clone per tick. A failed preparation leaves that actor's authoritative movement fields unchanged; diagnostics are separate outputs.

For flee, prepare the goal before replacing orders. For Blink, prepare range and endpoint admission before energy/cooldowns/pose. For speed/buff admission, validate before cost or buff replacement.

For collision accumulation, prepare both destination accumulator sums before storing either contribution from a pair; an overflow rejects that pair with evidence, preserving earlier valid contributions. Then prepare each actor's complete capped/proposed/slide result before changing its fields. Both zero-weight foundation guards remain in force. Rejecting one pair does not erase unrelated valid pair corrections, and diagnostic buffers are never queried as authoritative control state.

## Approved typed buff/order admission closure amendment

Read-only closure inventory found `Entity::issue_order(UseStim)` discards `apply_stimpack`'s bool, and world Overclock execution pays energy/cooldown before calling `apply_overclock`. A separate validator plus a legacy bool wrapper would conceal malformed state at those public entry points. Root requested the following narrow typed migration rather than preserving undocumented compatibility:

- `apply_overclock(spec)` and `apply_stimpack()` return `Result<bool, EntityAdmissionError>`: `Ok(false)` is ordinary HP eligibility rejection; invalid attack/speed multiplier, negative cost or unrepresentable prepared HP/fold is a typed error. All fields remain unchanged on either rejection. Prepare the ordered speed fold with the prospective refresh/addition before changing HP, duration or buff contents; retain existing buff IDs, costs, durations and replacement order.
- `issue_order(order, queue)` returns `Result<bool, EntityAdmissionError>`; normal accepted orders return `Ok(true)`. Immediate legacy UseStim delegates to the typed buff API, preserving `Ok(false)` eligibility. Queued orders remain scheduling intent; they do not debit costs at admission. No new ability definition/default behavior is introduced. Other order handling moves into one private infallible commit function; world Move/AttackMove preflight commits through a crate-private movement-only helper with concrete target/kind/queue arguments, so a fallible generic command cannot partially commit a multi-selection after validation.
- World immediate UseStim and Overclock ability execution preflight the full prospective speed against the current authored/upgraded base, buff fold and exact HP/energy payment before any resource/cooldown/buff mutation. Invalid public state emits existing fatal movement-invariant diagnostics with typed admission evidence. Ordinary HP/energy/cooldown rejection remains nonfatal. Queued execution prepares first: malformed arithmetic/rate/cost returns Err and preserves the queued request before fatal diagnostic emission. Ordinary eligibility rejection (Ok(false): HP, energy, cooldown, range or ordinary placement rejection) consumes the request exactly as the existing queued execution did; successful Ok(true) also consumes it. Preserve this policy for non-Overclock abilities; do not turn rejected ordinary requests into automatic retries. Add explicit low-HP/energy/cooldown consumption and malformed-state preservation regressions.
