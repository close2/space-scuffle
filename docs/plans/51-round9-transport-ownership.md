## Actual source findings and bounded goal

`SimWorld::load_unit_into_transport(unit_id, _transport_id)` ignores the carrier argument, sets a freely writable boolean, and clears the passenger's orders, route, velocity and target. It accepts missing/dead/foreign/self carriers and does not distinguish a real carrier from `EntityId(999)`. `Entity` has no carrier reference or passenger collection. No catalog transport capacity/capability is implemented. Existing projectile tests rely on the nonexistent999 carrier.

Plan45's `try_unload_unit_from_transport` checks an exact destination and a loaded boolean; it has no carrier to validate. Its actual documented policy is **destination-only** placement: full-radius map bounds, Ground conservative footprint/terrain connectivity, same-layer live circle occupancy, and registered-foundation rejection. Intervening terrain is irrelevant. Preserve that contract, including exact tangency, and do not infer boarding range or introduce a nearest-free endpoint. The48 appendix phrase about not teleporting through a cliff must not be interpreted as introducing a new sweep between pickup/carrier/unload positions.

Existing loaded predicates suppress targeting, movement, collision, production-exit occupancy and several client controls. The audit also found missing presence gates: `update_vision` grants loaded actors sight/detection, `write_render_snapshot` still publishes their bubbles, phase2 hazards and all three splash loops (instant/hitscan, projectile-primary and ballistic) can damage them at stale pickup positions, and direct Move/Produce/ability APIs can schedule work after load. A real ownership lifecycle must close those holes rather than preserve a misleading “hidden passenger” flag.

`reap_dead_and_emit_shatter` currently collects dead IDs, prepares43 economy per entity, removes a possible foundation, releases captured supply/reservations and emits a shatter at that entity's position. Removing a dead carrier independently would strand passengers. A carrier/passenger group must prepare together so a bad passenger definition or ledger cannot remove the carrier first. Loaded passenger death must not produce a shatter at the stale pickup point.

## Authoritative representation and public APIs

Replace the public boolean with exactly one `pub(crate) transport_carrier: Option<EntityId>` on `Entity`. Constructor initializes `None`. External consumers receive only `transport_carrier() -> Option<EntityId>` and `is_loaded_in_transport() -> bool`, both documented, immutable, allocation-free derived queries. There is no public setter and no second mutable boolean. The crate-visible field supports canonical exhaustive checksum encoding and narrowly scoped deliberate corruption unit tests; ordinary integration fixtures use actual world transactions.

Do not store an authoritative passenger Vec on carriers. `SimWorld::has_transport_passengers(carrier) -> Result<bool, TransportInvariant>` validates the requested carrier identity/link neighborhood and answers by deterministic entity iteration; include dead passengers awaiting reap because their captured lifecycle still exists. A read-only `transport_passengers(carrier)` iterator may be exposed if an actual caller needs IDs, in sorted EntityId order, without allocating a collection. No speculative inverse cache is required. O(N) rare inverse queries are acceptable; do not invoke one per actor during every tick. Whole-world validation scans each entity once, resolves each existing link by BTreeMap lookup, and detects nesting by checking the carrier's own Option, O(N log N) without O(N²) inverse scans.

New `transport` module owns link validation, admission types and load/unload preparation. Proposed surface:

- `validate_transport_links(&self) -> Result<(), TransportInvariant>`: deterministic first-invalid-link evidence, no repair or mutation.
- `try_load_unit_into_transport(&mut self, passenger, carrier) -> Result<TransportReceipt, TransportAdmissionError>`: one exact pair transaction.
- `try_unload_unit_from_transport(&mut self, passenger, destination) -> Result<TransportReceipt, TransportAdmissionError>`: same existing method name/arguments, intentionally migrates its return type to represent both ownership and45 placement failures. `TransportReceipt` records passenger/carrier and action; it is derived output, not authoritative state or a new command outcome stream.
- Existing bool load/unload wrappers remain only as explicitly documented source-compatibility conveniences because current callers use them. They delegate once to typed transactions. Ordinary rejection returns false; invariant failures must already have emitted an exact `SimulationDiagnostic::TransportInvariant` (or the existing movement/production diagnostic for a wrapped domain error), so a bool cannot hide corruption. Migrate repository tests to typed results except dedicated wrapper behavior tests.

`TransportAdmissionError` distinguishes ordinary missing passenger/carrier IDs, same identity, dead/incomplete participants, different valid owners, already-loaded passenger, loaded carrier, passenger with passengers, foundation passenger, Busy passenger, NotLoaded, dead carrier during unload, and `Destination(DisplacementAdmissionError)`. `TransportInvariant` distinguishes invalid player slot, map key/entity ID mismatch, missing live archetype, dangling/self/cross-owner/nested stored link, loaded foundation, illegal stored passenger work/channel state and malformed linked completion state. Rejected new requests are ordinary errors; an already-stored impossible relation is corruption. Include actual passenger/carrier IDs in evidence, never a generic false or arbitrary replacement ID.

Add a TransportInvariant diagnostic variant through the existing diagnostic channel.38's real client already stops/reports diagnostic failures; verify its exhaustive matches still compile and consume this variant. Do not overload CombatEventVisual, introduce transport player commands, or change RenderSnapshot layout.

## Load admission and atomic commit

Validation order is deterministic and documented: validate existing transport graph; resolve both map entries and verify key/EntityId consistency, archetypes and valid owner slots; reject equal IDs; require both alive and completed; require equal actual owners. Then reject a loaded passenger, loaded carrier, passenger with any registered passengers, and passenger registered as a map foundation. A dome-shaped passenger without its required foundation is corruption, not a way to evade the foundation rule.

The passenger must have no paid `production_queue`, no `channeling_remaining_ticks`, and no `pending_ability`. Reject those as typed Busy without cancelling/refunding/rescheduling anything. Successful loading clears exactly the ordinary order queue, current target and funnel route, zeros velocity and sets the carrier Option. It retains weapon phase (including any stored windup target ID/remaining ticks) and weapon cooldown; do not describe this as cancelling/resetting windup. No projectile or hazard already committed in the world is revoked. Preserve all HP, shields, energy, buffs, modes, captures and43 supply values. Weapons cannot advance while loaded. A mode or immobility flag alone is not a new capacity/category restriction; foundations and actual busy state are the explicit rules.

The carrier may have its own paid production queue and may continue its ordinary work while carrying; loading must not clear or debit carrier fields. Passenger Busy restrictions apply to the actor whose normal world participation is suspended. A carrier's existing channel is not interrupted by adding a passenger and does not itself make the passenger Busy. If root requires a stronger carrier rule, approve it explicitly before implementation; do not infer it from a nonexistent transport capability.

After all checks, commit only the passenger carrier Option, empty ordinary order/route, zero velocity and `current_target=None`, matching the previous accepted load effects. Keep authoritative pickup position and pos_at_tick_start unchanged; those coordinates become dormant data rather than a world presence. Do not continuously copy carrier position into the passenger or use pickup position for sight/damage/rendering. Do not reset animation, vitals, timers, resources, ID allocation, map occupancy, captured supply or paid carrier jobs. Rejection must preserve complete entities/map/economy/allocator/checksum; derived diagnostic output is the only permitted error-side effect.

No distance, movement layer, capacity, transport archetype name or authored boarding capability is invented. This is an explicit low-level embedding/setup operation using arbitrary otherwise eligible entities; exposing player boarding requires a future capability/data/UI plan.

## Unload admission and exact endpoint

Validate the stored graph and passenger first, then require its actual carrier reference and an existing alive/completed same-owner carrier. A dead carrier awaiting reap is a legitimate death transition but cannot be used to rescue cargo through unload. Missing carrier or owner/identity mismatch is corruption. Dead/incomplete passenger is ineligible. Check registered-foundation rejection directly for the passenger, preserving that specific diagnostic for a foundation even when it is not loaded; this retains the existing45 foundation boundary test.

Then invoke the existing `validate_displacement_destination` without mutating anything. Preserve its full-radius bounds, conservative Ground footprint, same-layer live occupancy, Air distinction and exact tangent inclusion. The carrier remains a normal live obstacle if its collision layer overlaps the passenger; it is not automatically exempt. A loaded passenger's stale pickup position is not an obstacle. There is no fallback point, carrier-relative snap, path sweep, unload range or cargo-order retention invention.

On success clear only the Option, set exactly the requested position, zero velocity and clear ordinary orders/route as45 currently does. Retain existing pos_at_tick_start/current-target/other-field behavior; load had cleared the target. Any failure preserves every authoritative field including link, timers, position, queue and supply. Public displacement validation remains usable for Blink, so do not globally forbid a loaded actor there: unload needs that query. Instead direct ability admission rejects loaded casters before ability payment, and unload owns the allowed loaded-to-world transition.

The existing unload foundation regression will now match the explicit wrapped `Destination(RegisteredFoundation(...))` error. Tests must assert the precise new typed result, not weaken it to `is_err()`.

## Death, group preparation and43 economy

Project policy from the48 appendix: passengers die with their carrier; no emergency ejection. Independent passenger death removes only that passenger. Loaded deaths never emit individual stale-pickup shatters. Carrier death retains its actual normal shatter; other unrelated deaths retain normal events. This is an explicit Space Scuffle lifecycle rule, not an SC2 parity assertion.

Before reaping, validate graph and43 supply ledger. Collect deterministic death roots in EntityId order: an actually dead uncarried actor, or an independently dead passenger whose carrier remains alive. A dead passenger whose carrier is also dead belongs to that carrier's group and must not be scheduled twice. No nesting means a carrier root contains exactly itself and all direct passengers, living or dead. Group members are sorted by ID using retained scratch; no global per-frame clone, random hash set or duplicated authoritative passenger list.

Prepare **the entire death group** before modifying HP, entities, map or economy. Do not set passengers' HP to zero first: a later preparation failure must not partially kill a group. Reuse43's captured-supply/reserved-job release and definition/foundation validation. Factor `prepare_reap` so its existing formula can be evaluated against a staged `PlayerResources` value rather than always reading unchanged live resources. Fold each member's release into staged economy in stable order, validating checked usage/provider totals and the200 effective cap. Do not implement a second accounting formula. The passenger's captured contribution persists until actual committed removal; the carrier's paid queue reservation is released once alongside its own supply.

Only the root can be a registered foundation because loading a foundation passenger is rejected. Validate its complete existing footprint before commit. Perform the one fallible `remove_structure` operation, if present, **before** infallible entity/economy commits; its current only Result error is missing ID, and the preceding bounds/occupancy validation protects indexing. No other fallible domain operation follows successful map removal. Remove every prepared member and assign staged economy as one exclusive group commit; then recompute clearance if required and publish only allowed shatter events. No callback/user code/interleaved mutation may occur in commit. Do not convert failed removals to success or invoke expect/panic bridges.

Failure precedence is explicit. First, a global invalid transport graph suppresses the **entire** gameplay tick/reap invocation; the tick-boundary clock/diagnostic/checkpoint behavior remains as specified above. Reap also validates the43 supply ledger before any group and suppresses that entire reap invocation on failure. This does not move every existing43 ledger check ahead of phase1 or claim whole-tick economy rollback. In either failed reap precondition, no group is removed, no supply released, and no shatter emitted. Missing archetype on a linked passenger/carrier is in this global category. After those validators succeed, a domain preparation failure local to one death group (for example a registered carrier foundation whose actual occupancy no longer matches its validated metadata) preserves that whole group/map/economy and emits the typed failure; unrelated valid groups may still commit. An unrelated unlinked dead actor with a missing definition similarly fails its own group preparation. No whole-world rollback is claimed. A second reap after successful removal is a no-op, with no duplicate release or shatter. Tests must distinguish global missing-passenger-archetype failure (all groups preserved) from local foundation-preparation failure (failed group preserved, unrelated valid death committed).

## Checksum and compatibility

Current canonical schema is3. Replace the boolean's exact field slot with Option encoding: None tag0, Some tag1 followed by carrier EntityId as fixed little-endian u32. Bump to schema4 **if no intervening authoritative schema change landed**, otherwise increment the then-current schema once and update exact-byte fixtures. Both full-world and partial entity/projectile digests carry this schema header. The relation affects future deaths and must hash differently even when two carriers have identical positions/stats. Derived receipt/scratch/inverse-query results remain excluded.

`Entity` is not currently Serde-serialized as a save state; RenderSnapshot has no transport relation, and `TickBundle` carries only an optional checksum without a schema-version field. No actual save decoder or session-version negotiation was found. Therefore implement the concrete source/API and canonical-checksum compatibility change and tests, not a speculative save codec or invented replay rejection API. Historical checksum bytes are intentionally incompatible; callers must use the public schema version in any external compatibility envelope. A future importer containing only loaded=true cannot infer a carrier and must explicitly reject it, but there is no such importer to implement here.

The external checksum mutation test currently writes the boolean directly. Remove that obsolete mutation case and add valid world transactions that distinguish None/Some and carrier A/B; use isolated unit tests inside the crate for deliberately corrupted private links. Add exact Option byte tests in the canonical encoding module and update schema3 expected headers/production queue byte fixture. Do not weaken exhaustive Entity destructuring.
